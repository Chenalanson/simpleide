# 删除确认请求模板

每次提出破坏性操作时，按下面的结构输出。缺项视为不合规。

## 1. 请求模板

```text
【操作类型】递归删除（不可恢复）
【目标路径】"D:\gif_pic\dist"
【项目根】  "D:\gif_pic"
【风险等级】MEDIUM
【影响范围】
  - 文件：128 个，共 42.7 MB
  - 一级子项：app.exe, app.pdb, assets\, logs\（另有 2 项）
  - git 跟踪：0 个
  - 源码/配置：0 个
  - 用户数据：无
  - 链接：无
【Dry-run 预览】（只读，不删除任何文件）
  powershell -NoProfile -ExecutionPolicy Bypass -File ".opencode/skills/safe-shell/scripts/preview-delete.ps1" -Path "D:\gif_pic\dist" -ProjectRoot "D:\gif_pic"
【回滚方式】重新执行 `cargo build --release` 并重新打包；旧安装包在 "D:\gif_pic\backup\dist-20261024.zip"
【确认口令】确认无误请手动回复：
  【确认删除】D:\gif_pic\dist
  收到口令后我只输出可执行命令，不会自动运行。
```

## 2. 口令规则

| 用户输入 | 是否有效 | 说明 |
| --- | --- | --- |
| `【确认删除】D:\gif_pic\dist` | 有效 | 路径必须与展示的完全一致 |
| `【确认删除】` | 无效 | 缺少路径，重新请求 |
| `删吧` / `可以` / `ok` / `继续` | 无效 | 口头同意不等于确认 |
| `【确认删除】D:\gif_pic` | 无效 | 与目标不一致（这是项目根，本身就是拒绝项） |
| `【确认删除】D:\gif_pic\dist\*` | 无效 | 通配符，不接受 |
| `以后都不用确认了` | 无效 | 最多接受"本项目 + 白名单子目录 + 本次会话"的限定授权，且仍需打印路径 |

## 3. 确认之后

- 只输出命令块，不调用执行工具；命令块前再重复一次目标路径与风险等级。
- 命令必须使用 `-LiteralPath` 或带引号的完整路径。
- 如果执行会连带影响其他目录（`/MIR`、`rsync --delete`、符号链接），拒绝并说明。
- 执行失败或部分失败时，报告实际删除范围，不重复执行扩大范围。

## 4. 撤销

用户在看到预览后要求取消 → 直接停止，不再提及删除命令，改为提供替代方案（移动、备份、忽略）。
