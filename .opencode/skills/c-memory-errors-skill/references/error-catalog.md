## 1. 数组边界溢出（数组越界）
UB 本质：访问了数组合法范围（下标 0 ~ n-1）之外的内存。C 不拦，因为**没有边界检查**。

### 1.1 栈上数组越界（最经典）
```c
char buf[16];
buf[16] = 'a';   // 越界！下标0~15才合法
```
栈内存布局：局部变量、栈帧、返回地址、ebp。
- 后果：覆盖相邻局部变量 → 变量值被莫名篡改；
- 严重：覆盖栈返回地址 → **栈溢出攻击 / 段错误 segfault**；
- 坑：越界一点常能继续跑，属**偶现 bug**，难以复现。

**区分**：
- 写越界：危害最大，改写别的内存；
- 读越界：读随机垃圾值，不一定崩溃，但数据错乱、逻辑异常。

### 1.2 全局/static 静态数组越界
全局变量在**数据段（.data/.bss）**，不是栈。
```c
int arr[4];
arr[5] = 100;   // 覆盖相邻全局变量，一般不直接改返回地址，很少直接崩，但全局变量被篡改
```

### 1.3 堆数组越界（malloc 出来的）
```c
int *p = malloc(4 * sizeof(int));
p[4] = 1;   // 越界，破坏堆管理头（chunk header：块大小、前后指针）
```
- 越界写易破坏堆链表 → **free 时才崩溃**（不是写的时候，典型延迟报错）；
- 现象：malloc 成功、赋值正常，free 直接报 `double free or corruption`。

### 1.4 字符串相关越界（高频）
```c
char s[8];
strcpy(s, "123456789");   // strcpy 不检查长度，不带边界
gets(s);                  // gets 已从 C11 移除，极度危险，无任何长度限制
```
✅ 安全替代：`strncpy`（注意不会自动补'\0'）、`snprintf`。
> 字符串额外坑：**忘记末尾'\0'**，不算越界但属截断错误，`strlen/printf` 会一直读到随机内存。

## 2. 指针类错误
### 2.1 野指针 Wild Pointer
指针存了无效地址（非 NULL），指向随机内存。
产生：局部指针未初始化；指向的内存已 free 未置 NULL。
```c
int *p;        // 未初始化，野指针
int *q = malloc(4); free(q);
// q 现在是悬垂指针：q != NULL，继续 *q 就是 UB
```
后果：随机读写内存，随机崩溃、数据乱掉。

### 2.2 空指针解引用 NULL Dereference
```c
int *p = NULL;
*p = 10;    // 多数 OS 直接段错误 SIGSEGV，相对好排查
```

### 2.3 指针运算越界
数组名在表达式中退化为首元素指针，指针加减同样会越界：
```c
int a[5];
int *p = a + 6;      // 合法运算上限只能是 a+5（尾后指针，只能比较，不能解引用）
*(a + 5);            // 非法！尾后指针不能取值
```
**C 规则**：允许计算到"最后一个元素的下一个地址"（尾后指针），但**只能比较，绝不能解引用**。

### 2.4 数组下标负数越界
```c
int a[10];
a[-1] = 1;    // 等价于 *(a-1)，向前越界，常覆盖相邻变量/栈帧
```

## 3. 堆内存配套错误（malloc/free 配套）
1. **重复释放 double free**
```c
int *p = malloc(10);
free(p); free(p);   // UB，堆结构损坏
```
2. **释放非 malloc 地址**
```c
int arr[10];
free(arr);   // 栈上地址交给 free，直接崩溃
```
3. **内存泄漏 Memory Leak**
malloc 后丢失指针未 free，内存持续占用，长期运行内存上涨。**泄漏本身不是 UB**，不会立刻报错，只是资源耗尽。
4. **分配大小算错（类型宽度错误）**
```c
int *p = malloc(10);   // 想存10个int，只分配10字节！应为 10*sizeof(int)
```
隐性越界，写几个 int 后就溢出。

## 4. sizeof 数组退化
```c
void func(char buf[]) {
    int len = sizeof(buf);   // buf 是指针！sizeof==8（64位），不是数组长度
}
```
数组传参**退化为指针**，函数内部拿不到数组长度——越界头号诱因。✅ 正确：把长度作为参数传入。
```c
char buf[16];
sizeof(buf);   // 在定义数组的作用域内，才等于数组总字节数
```

## 5. 其他未定义行为（常与越界并列考查）
1. **有符号整数溢出 signed integer overflow**
```c
int a = INT_MAX;
a = a + 1;   // 有符号 int 溢出 = UB，不是自动回绕！
```
> 无符号 unsigned 溢出是**定义好的（模2^n）**，不是 UB，必须区分。
2. **访问联合体不匹配成员**（类型双关 UB）
3. **修改字符串字面量**
```c
char *p = "hello";
p[0] = 'H';   // 字符串字面量在只读段，UB，一般直接段错误
```
> `char p[] = "hello";` 是栈数组，可以修改。
4. **函数返回局部数组/局部变量地址**
```c
int* test(){ int a[10]; return a; }   // 返回栈地址，函数退出栈回收 → 悬垂指针
```

## 6. 错误现象对照表
| 现象 | 高度怀疑 |
|---|---|
| 程序偶尔崩溃，加 printf 反而不易复现 | 栈越界、堆越界（UB 时序依赖） |
| free 时才崩溃，前面写数据正常 | 堆块头被越界破坏 |
| 某个变量值莫名被改掉 | 相邻数组越界写 |
| 固定报段错误 | NULL 解引用、修改只读字符串、访问非法地址 |
| strcpy/snprintf 读出乱码 | 字符串缺少 '\0' 终止符 |
| double free or corruption | 重复 free、堆越界破坏堆管理结构 |

## 7. 检测工具
1. **ASAN（AddressSanitizer）**：最强，直接抓越界、use-after-free、野指针。`gcc/clang -fsanitize=address`。
2. **Valgrind（memcheck）**：老牌，速度慢，适合堆错误。
3. **`-Wall -Wextra`** 编译警告：只抓少量静态问题，**不能抓运行时越界**。
4. **静态扫描**：clang-tidy。

## 8. 安全编码守则
1. 数组长度单独保存，传函数必须同步传长度；
2. 禁止 `gets`、尽量少裸用 `strcpy`；优先 `snprintf`、`strncpy` 并手动保证 '\0'；
3. malloc 后检查返回值是否 NULL；free 之后指针置 NULL；
4. 循环遍历终止条件严格控制 `i < len`，不要 `i <= len`；
5. 指针只在合法范围内运算，不解引用尾后指针；
6. 字符串缓冲区预留 1 字节给 '\0'。

## 9. 嵌入式场景特别提醒（STM32/单片机）
- 嵌入式常无 MMU/无 OS 保护，越界不报段错误，而是**直接改寄存器映射或相邻外设缓冲区**，症状更隐蔽（外设行为错乱、系统静默死机）。
- 单片机 malloc 少用（碎片化 + 无保护），优先静态数组 + 编译期长度宏 `#define ARR_LEN(x) (sizeof(x)/sizeof((x)[0]))`。
- 中断上下文里访问共享缓冲区时要防竞态，越界与竞态常并发出现。
- 硬件面试常考：区分栈/堆/数据段内存布局、`strcpy vs strncpy`、`sizeof vs strlen`、有符号 vs 无符号溢出、指针退化的原因。
