# 固定输出模板（模板 A–H 全文）

> 本文件是 **L3 外部输出层的模板库**。L1 判定模板类型（T1–T8）后，L3 按对应模板（A–H）渲染快照；严格照骨架输出：小节编号、标题与表格行列写死，禁止增减、禁止自创分点。

### 3.1 模板 A — T1 整机/新功能开发

```
0. 任务判定：T1 整机开发｜链: collect_requirements→index_context→query_docs?→read_context?→plan_ledger→write_ledger→plan_architecture→codegen_by_layer→framework_write→consistency_check→build→serial_cli?｜模板 A
1. 上下文收集
   1.1 已知/缺失/假设表（项|内容|来源/假设说明）
   1.2 复用资源清单（文件:对象名|用途）
2. 需求拆解
   2.1 硬件资源需求表（功能|外设类别|路数|关键参数|隐含需求）
   2.2 软件需求表（节拍|状态|协议|数据量|机制）
   2.3 冲突预判（冲突双方|原因|替代方案）
3. 台账设计（规划表|时钟规划|分配原则|资源预算）
4. hardware.dts 台账完整内容（文件名 hardware.dts + 保存路径说明 + 代码块）
5. 架构确认与代码实现
   5.1 架构确认表（层|目录|职责|典型文件|可调用下层；来源：默认/自定义/沿用）+ 根目录分层骨架清单（目录|动作：新建/沿用|本次落点文件）+ 目录树（照 architecture.md 第 3 节骨架）
   5.2 APP 层（app_init 三步法；app_sched_thread / app_loop_thread）
   5.3 MID 层（调度器/设备管理器/解释层/日志与错误码）
   5.4 BSP/MODULES 模块驱动（新模块按 M-DEV 步骤：句柄|接口|错误码）
   5.5 BSP/PERIPHERAL 外设驱动（片上外设封装，参数取自台账）
   5.6 最小改动说明表（文件|位置|原值|新值/动作|原因）
6. framework.md（按 framework-template 三章完整产出）
   6.1 分层架构（层级表|目录树|调用方向图|依赖矩阵）
   6.2 软件架构五维度（执行范式|调度模式|设计模式清单|模块化要点|共享数据保护）
   6.3 运行视图（启动调用链|调度时间线|中断抢占表|事件上下文链|耗时预算表[预估+实测待回填]）
7. 核对
   7.1 台账-代码一致性表（8 维，照 checklist.md 第 1 节列）
   7.2 待核对事实表（项|依据位置|状态）
   7.3 健壮与安全项清单
8. 构建验证与排查
   8.1 se-build 实际构建结果（结果|错误/警告|用时）与检查点   8.2 排查链（编号步骤）   8.3 优化提示   8.4 串口 Debug（se-cli 实际输出|检查项|结论）
```

### 3.2 模板 B — T2 单外设增补（小任务默认模板）

```
0. 任务判定：T2 单外设增补｜链: index_context→read_context→query_docs?→plan_ledger→ledger_patch→codegen_by_layer→framework_patch?/framework_write?→consistency_check→build→serial_cli?｜模板 B
1. 架构确认与复用改动清单
   1.1 架构确认落点（所属层 + 完整相对路径；目标目录是否需新建；沿用现有架构写「沿用现有架构：<目录结构>」并给默认层→现目录映射表）
   1.2 复用资源表（文件:对象名|沿用理由）
   1.3 新增/修改项表（模块|文件相对路径|动作：新增/修改|所属层|目录状态：新建/已存在）
2. hardware.dts 台账节点片段
   2.1 dts 片段代码块
   2.2 取值来源表（台账字段|取值|依据：原值/手册章节/显式假设）
3. 代码实现（按层顺序，块前标注【层/相对路径:插入位置】，如【BSP/MODULES/bsp_sc8701.c】）
   3.1 APP 层调用点（app_init 步骤位置 / 任务注册点；无则写「无改动」）
   3.2 MID 层（调度注册/设备注册/解释接口；无则写「无改动」）
   3.3 BSP/MODULES 模块驱动（新模块：句柄|对外接口|错误码；沿用则写「沿用不改」+理由）
   3.4 BSP/PERIPHERAL 外设驱动（新增封装或沿用现有封装）
   3.5 最小改动说明表（文件|位置|原值|动作|原因；纯新增写「新增」）
4. framework.md 增量更新点
   4.1 变更小节清单（1.4 依赖矩阵 / 2.1 执行范式 / 2.2 调度与任务表 / 2.3 设计模式 / 3.3 中断表 / 3.4 事件链，逐项标注变更或「无变更」）
   4.2 受影响内容片段（对应小节替换文本；无变更写「framework 无变更」）
5. 台账-代码一致性表（8 维照 checklist 第 1 节；不适用写 N/A，禁止删行）
6. 待核对事实表（项|依据位置|状态）
7. 构建验证与排查
   7.1 se-build 实际构建结果（结果|错误/警告|用时）与检查点   7.2 排查链（≥3 步编号）   7.3 串口 Debug（se-cli 实际输出|检查项|结论）
```

```
   | 验证项 | 操作 | 预期结果 |
```

```
0. 任务判定：T4（报错类别：编译/链接/HardFault/运行现象子类）｜链: index_context→read_context?→collect_symptom→diag_hypotheses→diag_code→build→flash?→debug_start?→serial_cli?/observe?→issue_log(open)→minimal_fix→framework_patch?→build→regress→issue_log(resolved)→diag_cleanup→build｜模板 D

   | 项 | 内容 |
   |---|---|
   | 报错原文/现象 | |
   | 复现条件 | |
   | 相关文件与代码位置 | |
   | 观测值（寄存器/波形/日志） | |
   1.1 可能故障位置排序表（位置|支持证据|可能性：高/中/低|排除方法）
2. 诊断方案与诊断代码
   2.1 串口方案（命令/CLI 输出|预期）与无串口替代（LED 闪烁码/GPIO 脉冲/蜂鸣器/调试器 watch/寄存器/断点）
```
