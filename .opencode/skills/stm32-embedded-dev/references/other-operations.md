# T6 其他操作（受控扩展层）

T6 不是“绕过 T1–T5 的自由操作”，而是把删除、重命名、移动、工程配置、文档/报告维护、咨询/方案设计等**不属于硬件开发主流程**的请求收进一个可审计、可确认、可回退的扩展层。它分为 **T6-O 操作**（会产生文件或配置变更）和 **T6-C 咨询/设计**（只给分析和方案，默认不改文件）。具体故障诊断属于 T4，不在 T6 里改代码。

## 1. 适用与不适用

适用：

- 删除已迁移、重复、废弃的源文件/头文件/文档/资源。
- 重命名或移动文件、目录（协议落地前只给预览）。
- 修改 `C_SOURCES`、包含目录、宏、链接脚本、工程配置等构建元数据。
- 维护 `hardware.dts`、`framework.md`、资源报告、TODO 清单。
- 清理构建产物、临时文件、旧备份（用户明确指定范围时）。
- 生成报告、检查工程一致性（只读）。
- 架构/外设/器件选型、方案对比、可行性分析、设计评审（T6-C，见 `consulting-design.md`）。

不适用：

- 修改外设、时钟、引脚、中断、DMA、状态机等硬件/代码逻辑——仍按 T1–T5。
- 具体故障定位、诊断代码和修复——按 T4（`diagnostics.md` / `debug-playbook.md`）。
- 任意 shell、注册表、网络下载、安装软件、Git 提交/推送。
- 删除工程根、目录、`.simple-embedded`、`.git`、`.se-workspace`、构建/生成目录。
- 批量删除“看起来没用”的文件；没有用户明确目标时不得清理。

## 2. 操作目录（当前与候选）

| 操作 | 当前状态 | 风险 | 执行方式 | 确认要求 |
|---|---|---|---|---|
| 删除普通文件 | **已支持** | 高 | `se-delete path=相对路径` | 独立删除卡片 + “删除文件”二次确认 |
| 修改/新建文件 | 已支持（T1–T8 通用） | 中 | `se-file` / `se-replace`（新建走 `write_file`，修改走 `patch_file`） | “应用全部”确认 |
| 删除空目录 | 未支持 | 高 | 只给手动步骤预览；O12 不覆盖目录删除 | 不执行 |
| 重命名/移动文件 | 未支持 | 高 | 只给命令预览（预览协议，不执行） | 需未来协议落地 + 二次确认 |
| 创建目录 | 未支持 | 低 | 只给命令预览（预览协议，不执行） | 需未来协议落地 |
| 修改 `C_SOURCES` | 不自动 | 中 | 删除后只给需移除条目预览，用户手动更新 | 在影响分析中列出 |
| 修改包含目录/宏 | 已有 UI/配置能力 | 中 | 工程配置或 Makefile 差异 | 说明影响并备份 |
| 修改链接脚本/内存布局 | 已有 UI 能力 | 高 | 只给建议/配置步骤 | 必须人工确认 |
| 维护 `hardware.dts` | 已支持（T5） | 中 | `se-replace`（`ledger_patch`） | “应用全部”确认 |
| 维护 `framework.md` | 已支持（T1–T8） | 低 | `se-file`（`framework_write`）/ `se-replace`（`framework_patch`） | “应用全部”确认 |
| 生成资源报告 | 已有 UI 能力 | 低 | 只读扫描 | 无需删除确认 |
| 咨询/方案设计 | 已支持（T6-C） | 低 | 只输出分析，不改代码 | 用户明确要文档时才 `write_file` / `patch_file`（O3 + 确认） |
| 清理构建产物 | 未支持 | 高 | 只给命令预览 | 需明确目录和二次确认 |
| 运行构建 | 已支持（T6 验证可用） | 低 | `se-build` 真实构建，引用回传 | 0 error 才算通过 |
| 烧录 | 未落地 | 高 | 只给预览，用户手动执行 | O1 + 用户确认 |

## 3. 删除协议（当前实现）

模型输出：

````se-delete path=Core/Src/bsp_usart_echo.c
旧实现已迁移到 BSP/PERIPHERAL，保留会重复定义。
````

规则：

- `path` 必须是工程内相对路径；禁止绝对路径、`..`、盘符。
- 只允许普通文件；目录、符号链接、生成目录、`.simple-embedded`、`.git`、`.se-workspace` 一律拒绝。
- 一次最多 10 个删除。
- IDE 先显示“AI 文件删除”卡片；用户点击“删除文件”后才执行。
- 执行前把文件复制到用户备份目录，并写 `ai-delete-<时间>.manifest.txt`。
- 执行后关闭相关标签页、清理断点/分屏/调试位置，并刷新文件树、符号、调用关系和架构面板；`C_SOURCES` 只给出应移除条目预览，由用户手动更新（没有注册任务自动同步构建元数据）。
- 删除前再次读取目标 mtime/size，与索引/生成时记录比对；任一变化即拒绝删除，要求重新生成或重新确认。
- `se-delete` 是真实执行请求，不是示例；表格、说明或命令预览中的示例必须放在普通 Markdown 代码块里，避免被 IDE 当成删除请求。

## 4. 后续协议建议（未落地，仅预览）

以下均为**未落地建议**，只可预览，不得写入任务链、不得声称已执行；正式白名单见 `contract-map.md` §4。为了让 T6 可扩展但不失控，未来若落地，按“预览 → 确认 → 执行 → 回退”增加，而不是开放任意命令：

| 建议名称（未注册、未落地，仅预览） | 用途 | 关键校验 |
|---|---|---|
| `se-rename old=新路径` | 重命名/移动文件 | 源存在、目标不存在、不覆盖、不跨工程；若未来落地，执行后由用户手动更新打开标签与 Makefile；未落地 |
| `se-mkdir path=相对路径` | 创建目录 | 父目录存在、目标不存在、不创建生成目录；未落地 |
| `se-clean target=build` | 清理构建产物 | 目标必须在白名单、先预览文件数/大小；未落地 |
| `se-config key=value` | 修改工程配置 | 只允许白名单键、显示旧值→新值、备份配置；未落地 |
| `se-run task=build` | 请求运行构建 | 不自动执行，只把命令填入构建卡片；未落地，正式构建仍走 `se-build` |

空目录删除不在建议范围：O12 只允许 `delete_file` 删除普通文件，目录删除只能给用户手动步骤。

每个协议都必须有：路径校验、冲突检查（打开且未保存、目标已存在、重复操作）、备份、执行结果、回退说明。

## 5. T6 工作流

先判定是 **T6-O 操作** 还是 **T6-C 咨询/设计**。

T6-O：

1. **操作清单**：把请求拆成动作、目标、原因、风险；列出不执行项。
2. **影响分析**：检查文件是否存在、是否被打开/未保存、是否影响 `C_SOURCES`/包含目录/链接脚本/工程配置；标注可恢复性。
3. **执行预览**：给出将执行的协议或命令、前置检查；需要用户确认的项单独列出。
4. **执行**：只执行用户确认的项；删除只走 `delete_file`（`se-delete`），未支持协议不假装执行。
5. **结果**：已完成、失败/跳过、备份位置。
6. **验证与回退**：用 `se-build` 真实构建/搜索/打开文件验证；烧录只给预览并等用户手动执行；给出从备份恢复或反向操作的步骤。

T6-C：

1. 复述目标、约束和假设，列出不做什么。
2. 给出 2–4 个方案（含“不改”的基线）和对比表。
3. 给推荐方案、触发切换的条件、风险和待确认项。
4. 默认不产生 `se-file`/`se-delete`；用户明确要求设计文档时，走 `write_file`（新文件，O3 + 确认，`se-file`）或 `read_file` → `patch_file`（已有文件，`se-replace`）；不得绕过 O3 直接写。
5. 用户决定实施后切换到 T1/T2/T3，不在咨询里偷偷改业务代码。

## 6. 常见场景

### 6.1 文件已迁移，删除旧实现

1. 确认新文件已存在且实现完整。
2. 检查旧文件是否仍在 `C_SOURCES`、是否被其他文件包含。
3. 输出 `se-delete`，说明删除原因。
4. 用户在删除卡片确认。
5. 用户手动从构建工程/`C_SOURCES` 移除旧条目（AI 只给预览），再验证构建不再引用旧文件；如失败，从备份恢复。

### 6.2 重命名模块（协议落地前）

1. 列出旧路径、新路径、受影响的 `#include`、`C_SOURCES`、文档引用。
2. 给出手工步骤或后续协议预览。
3. 不直接声称“已重命名”。

### 6.3 清理旧构建产物

1. 明确目标目录（只允许 `build/`、`Debug/`、`Release/`、`out/` 等白名单）。
2. 预览文件数和占用空间。
3. 用户确认后由 UI 的 Clean 按钮执行；AI 不直接删目录。

### 6.4 修改工程配置

1. 显示旧值 → 新值、影响范围、备份位置。
2. 只改用户明确指定的键。
3. 不修改 `.uvprojx`、不覆盖链接脚本、不写 `.simple-embedded` 之外的私有格式。

## 7. 审计与回退

- 删除备份：`%APPDATA%\SimpleEmbedded\backups\<工程名>-<hash>\ai-delete-<时间>/`。
- 修改备份：`%APPDATA%\SimpleEmbedded\backups\<工程名>-<hash>\ai-<时间>/`。
- 每次操作在卡片中显示备份路径；删除卡片只显示自己的备份。
- 回退：把备份目录中的相对路径复制回工程；Makefile 的 `C_SOURCES` 需要手工更新（无自动同步）。
- 不提供“一键撤销删除”，避免误恢复覆盖当前文件；恢复前先比较内容。

## 8. 禁止项

- 禁止把删除伪装成“清空文件内容”“改成注释”“写请手动删除”。
- 禁止删除未在操作清单中列出的文件。
- 禁止为了通过编译而删除用户代码、链接脚本、启动文件或工程配置。
- 禁止自动执行 `git clean`、`rm -rf`、注册表写入、网络下载、安装器。
- 禁止在用户未确认时移动/重命名文件；未落地协议只给预览。
