# 分层架构规范（S3.1 架构确认专用）

> 目录
> 1. 架构确认流程（S3 第一步，强制）
> 2. 默认架构层级表（用户未自定义时使用）
> 3. 默认目录树与构建友好性
> 4. 单向调用规则与依赖红线
> 5. 文件归属决策表（新文件放哪一层）
> 6. APP 初始化骨架（app_init 三步法）
> 7. 自定义架构适配规则
>
> 用法：S3 先完成架构确认（第 1 节），后续所有代码块必须标注所属层与目录；违反第 4 节依赖红线即返工。

## 1. 架构确认流程（S3 第一步，强制）

| 步骤 | 动作 | 产出 |
|---|---|---|
| A1 判定 | 检查用户是否给出自定义分层（层级名、目录、职责、调用方向）；现有工程是否已有目录结构 | 架构来源结论：`用户自定义` / `现有工程沿用` / `默认架构` |
| A2 确认表 | 输出架构确认表（层 \| 目录 \| 职责 \| 典型文件 \| 可调用下层）；默认架构直接套用第 2 节，自定义按用户描述重排 | 表 3-x 架构确认表 |
| A3 目录树 | 给出本工程目录树（第 3 节格式；自定义时替换目录名） | 目录树代码块 |
| A4 归属规则 | 按第 5 节决策表登记本次新增文件落点；现有工程沿用其既有目录，不强行迁移 | 文件落点清单 |
| Gate | ①每层职责无重叠 ②调用方向单向无环 ③每个待写文件有明确落点 ④现有工程目录结构已识别并沿用 | 不满足不得进入 S3.2 写代码 |

默认架构在用户未反对时直接采用，并在确认表首行注明「采用默认架构，可在 S3 开始前提出替换」。

## 2. 默认架构层级表

| 层 | 默认目录 | 职责 | 典型文件 | 允许调用 |
|---|---|---|---|---|
| 应用层 APP | `APP/` | 初始化编排；调度线程；循环线程；业务状态机任务 | `app.c`、`app.h` | MID、BSP/MODULES |
| 中间件层 MID-业务解释层 | `MID/` | 高级 API 封装与协议解释（如 `power_set("SC8701",8.20)` → `dev_write("SC8701",0x21)`） | `service_*.c` | MID 设备管理器、MODULES |
| 中间件层 MID-调度/设备/日志 | `MID/` | 非抢占调度器；设备注册与回调绑定；日志与错误码定义 | `task_sched.c`、`dev_manager.c`、`log.c`、`err_code.h` | MODULES、PERIPHERAL |
| 驱动层 BSP-MODULES（模块驱动） | `BSP/MODULES/` | 具体器件：显示屏、传感器、计量芯片、编码器、按键、显示模组 | `bsp_st7789v.c/.h`、`bsp_sc8701.c`、`bsp_ina199.c`、`bsp_key.c` | PERIPHERAL、MID 底层服务 |
| 驱动层 BSP-PERIPHERAL（外设驱动） | `BSP/PERIPHERAL/` | MCU 片上外设封装：SPI/I2C/ADC/PWM/UART/TIME/GPIO 基础操作 | `bsp_spi.c`、`bsp_adc.c`、`bsp_pwm.c`、`bsp_usart.c`、`bsp_time.c` | LL/HAL 库 |
| 硬件抽象层 HAL/LL | 库源码（不改动） | 寄存器统一封装、句柄管理 | CubeMX 生成代码、LL 源码 | 硬件层 |
| 硬件层 | — | 寄存器与实际电路 | — | — |

层间调用总方向：

```
APP → MID(解释层) → MID(设备管理器/调度/日志) → BSP/MODULES → BSP/PERIPHERAL → LL/HAL → 寄存器
```

## 3. 默认目录树（EIDE/VSCode + MDK 双构建友好）

```text
Project/
├── APP/
│   ├── app.c
│   └── app.h
├── MID/
│   ├── task_sched.c / task_sched.h      # 调度器
│   ├── dev_manager.c / dev_manager.h     # 设备管理器
│   ├── log.c / err_code.h                # 日志与错误码
│   └── service_*.c / service_*.h         # 业务解释层
├── BSP/
│   ├── MODULES/                         # 模块驱动（器件级）
│   │   ├── bsp_st7789v.c/.h
│   │   ├── bsp_sc8701.c/.h
│   │   ├── bsp_ina199.c/.h
│   │   └── bsp_key.c/.h
│   └── PERIPHERAL/                      # 外设驱动（片上外设级）
│       ├── bsp_spi.c/.h
│       ├── bsp_adc.c/.h
│       ├── bsp_pwm.c/.h
│       ├── bsp_usart.c/.h
│       └── bsp_time.c/.h
├── EIDE-GCC/                            # 构建工程文件
```

规则：源码按层放目录，不按 IDE 工程文件归类；第三方开源库统一放 `MID/` 或独立 `LIB/`，便于多 IDE 移植；构建工程只引用目录，不复制源码。

## 4. 单向调用规则与依赖红线

| 编号 | 规则 | 禁止行为 |
|---|---|---|
| D1 | 调用只能沿第 2 节方向向下；上层可直接使用下层暴露接口，不反向引用内部实现 | PERIPHERAL `#include` MODULES；MODULES `#include` APP |
| D2 | 同层依赖优先走 MID 公共服务（设备管理器/日志），不跨模块直接操作他模块私有变量 | MODULES-A 直接访问 MODULES-B 的 static/extern 变量 |
| D3 | 禁止循环包含：`.h` 之间不得形成 include 环；必要时用前向声明或句柄指针 | A.h include B.h，B.h 再 include A.h |
| D4 | APP 不直接操作片上外设寄存器/HAL 句柄细节；跨片外设访问经 MODULES 或 PERIPHERAL 接口 | app.c 直接调 `HAL_SPI_Transmit` 驱动具体器件时序 |
| D5 | 第三方库放 MID/LIB，只被上层调用；不反向依赖工程业务头文件 | 开源库 include `app.h` |
| D6 | 依赖关系写入 framework.md 第 1 节依赖矩阵；新增依赖先确认不违反 D1–D5 | 口头默认，无记录 |

## 5. 文件归属决策表（新文件落点）

| 待写对象 | 落点层/目录 | 判断依据 |
|---|---|---|
| 主初始化、调度循环、业务任务编排 | APP/ | 只做调用编排，无器件时序细节 |
| 面向用户语义的封装（设置电压、保护阈值配置） | MID/service_* | 名字是业务语义，不是寄存器/器件名 |
| 调度器、设备注册、日志、错误码 | MID/ | 跨模块公共机制 |
| 某具体器件驱动（屏、传感器、计量芯片、温感、按键板） | BSP/MODULES/ | 对应一颗外部芯片或功能板；内部可调用多个外设驱动 |
| 某片上外设封装（SPI1 收发、ADC 扫描、PWM 通道、UART 收发、时基） | BSP/PERIPHERAL/ | 对应 MCU 外设实例，不含外部器件协议 |
| 器件协议帧解析与状态机 | 跟随器件放 MODULES；通用协议框架放 MID | 专用解析随器件，通用机制独立 |
| 第三方开源库、协议栈 | MID/ 或 LIB/ | 不修改源码，仅封装适配层 |

## 6. APP 初始化骨架（app_init 三步法）

固定顺序，不得跳步；步骤内为默认示例，参数以台账为准。

```c
/*
 * 软件架构链：应用层 → 中间件（日志/错误码/设备管理） → 驱动层(模块驱动→外设驱动) → 硬件抽象层(LL/HAL) → 硬件层
 */

void app_init(void)
{
    LL_SYSTICK_EnableIT();                 // 滴答中断：非抢占调度时基（1ms）

    // 步骤1：外设使能（PERIPHERAL 层初始化，依赖硬件时钟已开）
    spi_init(SPI1);                        // SPI1 初始化
    adc_init_dma(ADC1, 1);                 // ADC1 + DMA 初始化
    pwm_init(TIM1);                        // PWM 定时器初始化
    usart_init(USART1);                    // 串口初始化
    time_init();                           // 软件时基/周期定时器初始化

    // 步骤2：设备初始化（MODULES 层，必须在外设初始化完成之后）
    st7789v_init();                        // 屏幕器件初始化
    pid_init();                            // 算法/补偿器实例初始化
    sc8701_init();

    // 步骤3：任务时间变量/调度注册（调度器层）
    freedom_set_time(&multi_menu_timer, 5); // 周期任务时间变量，单位 ms
    // 任务分类：周期性（每次到点重赋值）/ 一次性（事件触发后再赋值）/ 条件性（满足条件赋值）

    LL_mDelay(200);                         // 器件上电稳定等待（仅初始化阶段，任务循环内禁止长阻塞延时）
}

/* 调度线程：非抢占式时间片触发，检查时间变量到点后调用任务 */
void app_sched_thread(void)
{
    freedom_task_sched();
}

/* 循环线程：连续执行状态机任务（瞬时判断，不挂时间间隔） */
void app_loop_thread(void)
{
    multi_menu_ui_task();                  // 菜单状态机
    sc8701_task(run_flag);                  // 器件状态机
    ovp_task();                            // 过压保护
    ocp_task();                            // 过流保护
    otp_task();                            // 过温保护
}
```

规则：

- `app_init` 只编排调用，不实现器件细节；每步注释标明所属层。
- 步骤 1 失败（初始化返回错误）进入错误上报与安全态，不继续步骤 2。
- 新增外设时先补 PERIPHERAL 初始化，再在步骤 2 补对应 MODULES 初始化，顺序不可反。

## 7. 自定义架构适配规则

| 情形 | 处理 |
|---|---|
| 用户给出层级名（如 HAL/BSP/APP/OS 层、driver/app/service） | 按用户命名生成层级表与目录树；保留「自上而下单向依赖」原则 |
| 用户现有工程已有目录（如 `User/`、`Drivers/`、`Application/`） | 沿用现有目录名，将默认层职责映射到现有目录；输出映射表（默认层 → 现工程目录），不新建平行目录 |
| 用户指定 RTOS 架构（任务文件独立、队列/互斥件目录） | 在 MID 层增加 OS 机制目录；调度章节引用 `software-arch.md` 抢占式模型；APP 层为任务函数集合 |
| 层级数少于默认（无 MID 层） | 将解释层与设备管理器职责并入 MODULES 层公共头；架构表如实记录，不强行补层 |
| 架构变更（中途调整目录/分层） | 先更新 framework.md 第 1 节与确认表，再移动/调整代码；改动记入最小改动说明表 |
