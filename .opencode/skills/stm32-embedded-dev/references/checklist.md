## 1. 使用方法与销项流程

1. 生成台账与代码后立即输出本清单，与台账 TODO 汇总块、代码 TODO 注释一一对应。
2. 核对顺序：先台账-代码一致性（第 2 节，快速发现漏配/双写不一致）→ 一级手册事实 → 二级参数复算 → 三级完整性与安全。
3. 销项方式：核对通过后删除对应 TODO 注释并标注来源；发现错误先改台账（参数单一来源），再同步代码，最后销项。
4. 来源标注简写：`RM-x.y`、`DS-Table n`、`SCH-U3`、`BOM`；代码位置标注 `文件:函数/行号`。

## 2. 台账-代码一致性核对（阶段 4 第一项）

输出一张对照表，逐资源填「台账记录 → 代码位置 → 状态（一致/待改/缺失）」：

| 核对维度 | 核对内容 |
|---|---|
| 实例对应 | 台账每个 `status="okay"` 实例，代码中有对应初始化/句柄；代码用到的外设台账均有登记 |
| 引脚对应 | 台账引脚组的端口/引脚与 GPIO 初始化结构体一致；复用号 TODO 同步落实 |
| 参数同源 | 波特率、通道号、PWM 频率、总线速率、器件地址在代码中的取值与台账一致；参数集中在 `bsp_conf.h` 宏，不散落函数体 |
| 通道顺序 | 台账通道 label 列表顺序 = DMA 数组下标/采集序列顺序 |
| 中断/DMA | 台账 `interrupts`/`dmas` 与 NVIC 配置、DMA 句柄通道一致；ISR 函数名与启动向量一致 |
| 安全节点 | 台账刹车/使能/看门狗节点在代码中有初始化与故障处理实现，动作方向与 `safe-state` 一致 |
| 绑定视图 | `app-bindings` 中每个用途都能在代码业务层找到对应使用点；无台账未登记却被代码直接使用的引脚/外设 |
| 最小改动 | 现有工程中未被要求改动的函数、初始化、引脚配置保持原样；新增片段有文件与插入位置说明 |

不一致处理原则：台账为参数来源；代码与台账冲突时以台账为准修改代码；台账与原理图/手册冲突时先修台账再改代码。

## 3. 一级清单：手册事实（必须逐项核对）

### 3.1 时钟与封装

- [ ] 芯片型号后缀与封装一致；可用引脚数量按封装表清点
- [ ] HSE 晶振实际频率（原理图位号）；是否有 LSE 32.768kHz 需求
- [ ] 规划主频不超过 DS 最大额定值；各总线分频后频率在额定范围内
- [ ] 定时器时钟倍频关系（APB 预分频 ≠ 1 时 ×2）已确认

### 3.2 引脚与复用

- [ ] 每个引脚组 `af` 号与 RM 复用定义表一致（最高频错误项）
- [ ] 引脚在封装上真实存在且未被电源/晶振/调试接口（SWD: PA13/PA14 等）占用
- [ ] 引脚方向与电气类型匹配：模拟脚不做复用数字功能；I2C 开漏特性备注；高驱动能力脚与负载匹配
- [ ] 无两个节点引用同一引脚（台账内交叉核对）
- [ ] 调试接口（SWD/JTAG）引脚未被挪用为普通功能（除非明确放弃调试并备注风险）

### 3.3 中断与 DMA

- [ ] `interrupts` 中 IRQn 与 RM 中断向量表一致；EXTI 线号分配无冲突
- [ ] DMA 控制器、通道号与外设请求映射符合 RM/DMAMUX 表；不确定项保持 TODO
- [ ] 中断优先级建议与后续分组方案兼容（台账 note 记录分组建议）

### 3.4 地址与器件

- [ ] I2C 子节点 `reg` 为 7bit 地址，与器件手册/BOM 一致
- [ ] SPI 片选索引与实际片选脚对应；片选有效电平记录正确
- [ ] 外部器件供电电压、上电时序、复位电平在 note 中记录并与器件手册一致
- [ ] 台账中出现的寄存器基址（若有）与 RM 存储器映射一致；无依据则不写

### 3.5 安全相关（电机/逆变/电源必核）

- [ ] 刹车输入节点存在，有效电平、滤波要求已记录
- [ ] 功率级使能节点存在，`safe-state` 为上电/故障安全电平
- [ ] 电流/电压采样通道的保护阈值规划有备注（阈值来源：硬件比较器/软件阈值）
- [ ] 故障关断动作链路（刹车 → 关 PWM → 断使能）在 note 中描述完整

## 4. 二级清单：参数复算

### 4.1 通信参数

- [ ] 串口：按 `field-mapping.md` 2.1 复算波特率误差，结论写入 note
- [ ] SPI：SCLK ≤ 从机最大频率；CPOL/CPHA 与从机时序图一致
- [ ] I2C：速率档位与上拉阻值、总线电容匹配（器件手册 + 硬件设计）
- [ ] CAN：速率与采样点与总线上其他节点一致；位段时间和为标称位时间

### 4.2 定时与采样

- [ ] PWM 频率按 2.2 复算；占空比合法范围（0~100%）记录
- [ ] ADC：通道号-引脚映射核对；参考源选择合理；采样时间满足源阻抗建立要求
- [ ] 多通道采集节拍 ≥ 通道转换时间之和 + 处理余量
- [ ] 周期任务节拍（备注值）与外设采样节拍匹配，无互相等待死锁隐患

### 4.3 外部时序

- [ ] 器件上电稳定等待、复位脉宽、片选建立保持时间与手册一致（note 记录）
- [ ] 显示/Flash 擦写等待时间等长操作有规划备注

## 5. 三级清单：完整性、代码健壮性与安全

### 5.1 台账内部一致性

- [ ] `app-bindings` 中每个引用都能找到对应节点（引用闭合）
- [ ] 每个 `status="okay"` 节点都有 `usage` 说明
- [ ] 命名符合规范：实例沿用芯片名、通道/引脚 label 统一风格、无同义词混用
- [ ] 引脚组在 `pinctrl` 区定义且被实例 `pinctrl-0` 引用，无孤立定义、无悬空引用

### 5.2 功能完整性

- [ ] 用户提出的每项功能都有对应节点或备注，无遗漏功能
- [ ] 输入类资源（按键、传感器、故障信号）与输出类资源（PWM、使能、指示）均覆盖
- [ ] 未使用资源有 `status="disabled"` 记录与处理建议，而非凭空消失
- [ ] 资源预算（引脚/通道/DMA/中断）有余量结论

### 5.3 健壮性与安全预留

- [ ] 关键资源有备用方案备注（主引脚不可用时的替代实例）
- [ ] 看门狗、复位、故障状态指示在规划中有体现（哪怕后续才实现）
- [ ] 低功耗场景：未用管脚处理、唤醒脚预留有备注
- [ ] 安全节点的故障动作描述可被后续开发直接理解（不需要反推）

### 5.4 代码健壮性与安全实现

- [ ] 外设初始化返回值已检查；失败有日志/回退，不继续访问句柄
- [ ] 等待/收发接口带超时退出，无裸死等循环
- [ ] 中断/回调内无阻塞调用、无打印重逻辑、无长循环；仅置标志或提交任务
- [ ] 接收/采集缓冲有边界判断；索引回绕正确；共享缓冲加 `volatile`
- [ ] 数组/字符串操作有长度上限；指针解引用前判空
- [ ] FreeRTOS（如启用）：队列/信号量创建成功再用；互斥量不跨阻塞持有；任务栈经水位估算
- [ ] 故障动作链代码落地：故障检测 → 停 PWM/断输出 → 关使能，方向与台账安全节点 `safe-state` 一致
- [ ] 现有工程改动仅限追加与指定位置修改，未重写已验证逻辑（对照最小改动规则）

## 6. 手册查阅指引（避免无效翻书）

| 台账内容 | 主要查阅位置 | 查什么 |
|---|---|---|
| 外设实例是否存在、编号范围 | RM 各外设章节开头 / 选型 DS 「功能概览」 | 该系列有几个 USART/ADC/TIM/SPI/I2C |
| 引脚复用 AF 号 | RM「Alternate function mapping」表 | 端口号-引脚号-AF 功能对照 |
| 中断号 IRQn | RM「NVIC interrupts table / vector table」 | 外设对应中断向量号与默认优先级 |
| DMA 请求映射 | RM「DMA request mapping」表（含 DMAMUX 章节） | 外设请求连到哪个 DMA 哪个通道 |
| 通道-引脚映射、参考电压、采样时间 | DS「Electrical characteristics / ADC characteristics」表 | ADC 通道号、内部基准电压值、推荐采样周期 |
| 电气极限、主频上限、封装引脚图 | DS「Maximum ratings」+「Pin definitions」 | 频率/电压限值、引脚功能标注 |
| 器件地址、时序、电平 | 器件数据手册（BOM 对应型号） | I2C/SPI 地址、CPOL/CPHA、上电时序 |
| 实际接线、网络名、晶振值 | 原理图 + BOM | 引脚实际走向、器件型号、阻容值 |
