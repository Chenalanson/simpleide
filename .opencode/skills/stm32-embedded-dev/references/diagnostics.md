# 故障诊断与可观测验证参考（diagnostics）

本文件用于 T4：先诊断“可能坏在哪里”，再写最小诊断代码，最后选择串口或非串口方式验证。

---

## 1. 诊断顺序

1. **信息采集**：现象、复现条件、最近改动、供电、时钟、复位、烧录方式、板卡版本。
2. **假设排序**：按“可能性 × 影响 × 排查成本”列可能位置，不直接猜一个。
3. **最小诊断代码**：每个假设对应一个可观测信号，改动尽量小，用宏/`#if DIAG` 包裹。
4. **构建**：`se-build` 实际 0 error；未通过不进入烧录/验证。
5. **烧录（按需，O1 + 用户确认）**：`flash` 只给预览并由用户执行；烧录后确认运行的是本轮新固件；未烧录时后续观测结果只能标 pending，不得当作本轮固件结论（O13）。
6. **验证**：
   - 有串口：`se-cli` 发 `help` / `info` / 专用诊断命令，回传真实输出（需满足 O13）。
   - 无串口：LED 闪烁码、GPIO 脉冲/电平、蜂鸣器、调试器 watch/寄存器/断点、按键/屏幕。
   - 无任何观测手段：`pending_ask(kind=observe)`，不得标记通过。
7. **记录**：用 `se-issue` 写现象、假设、观测、原因、解决方案。
8. **修复 + 回归**：最小改动，重新构建，重复验证；清理诊断代码。

## 2. 可能故障位置表

| 现象 | 高概率位置 | 诊断信号 |
|---|---|---|
| 完全不上电/不启动 | 供电、复位、BOOT 引脚、晶振、时钟配置、启动文件 | 电源电压、NRST、BOOT0、HSE/HSI、LED 心跳 |
| 烧录失败 | SWD/JTAG 接线、复位模式、读保护、时钟、探针配置 | 探针识别、`monitor reset halt`、读 IDCODE |
| 启动后立刻 HardFault | 栈溢出、空指针、中断向量、时钟/外设未初始化、数组越界 | HardFault 寄存器、栈指针、`bt`、LED 进入故障码 |
| 串口无输出/乱码 | 波特率、时钟、TX/RX 交叉、引脚复用、DMA/中断配置 | 示波器/逻辑分析仪、回环、`help`、GPIO 翻转 |
| ADC 读数异常 | 参考电压、采样时间、通道/引脚、DMA、校准 | 固定通道/内部参考、原始值、GPIO 触发 |
| PWM 无输出 | 定时器时钟、通道映射、比较值、刹车/使能、引脚 AF | 示波器、GPIO 翻转、寄存器值 |
| 中断不进入 | NVIC 使能、优先级、标志清除、向量表、外设中断使能 | 计数器、GPIO 翻转、断点、NVIC 寄存器 |
| 通信丢包/错帧 | 波特率误差、DMA 缓冲、空闲中断、协议长度、临界区 | 计数器、错误码、示波器、CLI 统计 |
| 运行一段时间死机 | 栈/堆溢出、内存越界、看门狗、电源跌落、中断风暴 | `_estack`/SP、watchpoint、看门狗计数、LED 状态 |
| 低功耗唤醒失败 | 时钟源、唤醒源、中断优先级、休眠模式 | 唤醒计数、GPIO 脉冲、RTC 标志 |

> 表中只是起点；必须结合用户板卡和代码给出具体文件/函数位置。

## 3. 诊断代码模式

### 3.1 LED 闪烁码（无串口首选）

```c
/* DIAG: 上电/故障阶段用 LED 闪烁次数表示状态；正式发布前移除或关闭。 */
static void diag_blink(uint8_t times)
{
    for (uint8_t i = 0u; i < times; i++) {
        bsp_led_set(1);
        delay_ms(120);
        bsp_led_set(0);
        delay_ms(280);
    }
}
```

约定示例：

| 闪烁次数 | 含义 |
|---|---|
| 1 | 进入 `main`，时钟初始化完成 |
| 2 | 外设初始化完成 |
| 3 | 主循环心跳 |
| 5 | 串口初始化失败 |
| 7 | HardFault / 断言 |
| 9 | 栈或内存检查失败 |

要求：

- 闪烁码表写进本轮回复与 `se-issue` 问题记录（`quality.issues`）；不要写进 `code_style.md`，用户能对照。
- 不要在 ISR 里长时间闪烁；ISR 只置错误码，主循环闪。
- 诊断代码用 `#if DIAG_LED` 或宏包裹，注明移除方式。

### 3.2 GPIO 脉冲/电平

```c
/* 用空闲 GPIO 或测试点输出阶段信号，示波器/逻辑分析仪观察。
 * DIAG_GPIO_Port / DIAG_Pin 优先使用 CubeMX Pinout 用户标签（把测试点标为 DIAG 时自动生成）；
 * 未生成时用下面的占位定义替换，端口/引脚必须按原理图核对并登记台账。 */
#ifndef DIAG_GPIO_Port
#define DIAG_GPIO_Port   GPIOB          /* TODO: 按原理图替换，禁止直接照抄 */
#endif
#ifndef DIAG_Pin
#define DIAG_Pin         GPIO_PIN_0     /* TODO: 按原理图替换，禁止直接照抄 */
#endif

#define DIAG_PIN_SET()  HAL_GPIO_WritePin(DIAG_GPIO_Port, DIAG_Pin, GPIO_PIN_SET)
#define DIAG_PIN_CLR()  HAL_GPIO_WritePin(DIAG_GPIO_Port, DIAG_Pin, GPIO_PIN_RESET)
```

用途：确认代码是否执行到某处、测量函数耗时、观察中断频率。没有示波器时可用 LED 代替。

### 3.3 心跳/计数器

```c
static volatile uint32_t g_diag_ticks;
/* 1 ms 时基或主循环递增；通过调试器 watch 或 CLI 读取。 */
```

用于判断主循环是否卡死、中断是否持续触发。

### 3.4 串口 CLI 诊断命令

有 CLI 时增加：

```text
diag status        输出启动阶段、复位原因、时钟、错误码
diag gpio <pin>    读/翻转测试引脚
diag reg <addr>    只读/受限写寄存器
diag stats         队列溢出、丢包、错误计数
diag clear         清计数
```

命令实现遵守 `references/serial-cli.md`：成功 `OK`，失败 `ERR`，输出 `key: value`。AI 通过 `se-cli` 发送并读取真实输出。

### 3.5 调试器观测

- `watch` 变量、`rwatch`/`awatch` 硬件 watchpoint。
- 查看 NVIC、RCC、GPIO、USART、DMA 寄存器。
- 断点在初始化前后、ISR、错误分支。
- HardFault 时看 `SCB->CFSR/HFSR/MMFAR/BFAR`、SP、`bt`。
- 没有串口但有调试器时，这些可以作为主要验证手段。

### 3.6 RTT / SWO（可选）

如果工程已有 SEGGER RTT 或 SWO，可用 `SEGGER_RTT_printf` / ITM 输出；没有时不要为诊断强行引入大依赖。

## 4. 有串口 / 无串口的验证模板

### 4.1 有串口

1. 构建 0 error；需要新固件时再烧录，并确认运行的是本轮产物（O1/O13）。
2. `se-cli`：`help` → `info` → 诊断命令；无响应先按 §4.2 转 `observe`，仍无手段则 `pending_ask(kind=observe)`。
3. 记录真实输出（`OK`/`ERR`、`key: value`）。
4. 对照假设表，标记确认/排除。

### 4.2 无串口

按可用硬件选择，至少一种：

| 可用资源 | 观测方式 |
|---|---|
| LED | 闪烁次数/节奏/常亮/呼吸 |
| 空闲 GPIO + 示波器/逻辑分析仪 | 阶段脉冲、PWM、中断频率 |
| 蜂鸣器 | 不同音调/次数 |
| 调试器 | watch、寄存器、断点、调用栈 |
| 按键/屏幕 | 进入不同测试模式、显示错误码 |
| 看门狗/复位计数 | 判断是否反复复位 |
| 以上都没有 | `pending_ask(kind=observe)`，不得标记通过 |

回复中必须写清“用户需要看什么、正常/异常分别是什么”，不能只写“请测试”。若表中手段一个都不具备（无 LED、无空闲 GPIO/仪器、无调试器、无串口），验证状态必须保持未验证，写 `pending_ask(kind=observe)` 说明缺少的观测设备和可替代方案，禁止写“通过/已排除”。

## 5. 诊断结果记录

| 假设 | 诊断动作 | 实测 | 结论 |
|---|---|---|---|

- 结论只能写“确认/排除/待确认”，并附证据。
- 未实际测试的项标“待确认”，不得写成已排除；无观测手段时写 `pending_ask(kind=observe)`，不得标通过。
- 修复后用 `se-issue` 记录：现象、原因、解决方案、相关文件。
- 诊断代码在修复后删除或关闭，并在回复中说明。

---

## 6. 安全与边界

- 不随意改写时钟、启动、看门狗、Flash 选项字节；必须改时先说明风险并让用户确认。
- 诊断代码不得引入阻塞、动态内存或大数组；不能影响正常时序。
- 高压/电机/功率板：先断电检查，遵循用户的安全流程；不要建议绕过保护。
- 没有把握的寄存器地址/位定义标 TODO，查 RM/DS，不猜。
