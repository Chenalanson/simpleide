# STM32 嵌入式开发执行规程（固定步骤版）

## 0. 执行总则（先读，区分两层）

**本规程分两层，严禁混淆：**

- **内部执行步骤（第 2 节 S0–S5 / P4 / S6）**：AI 自检与组织思路用，含「必做动作 / 固定产出 / Gate」等说明，**不得原样或改写复述到用户回复中**。
- **对外输出小节（第 3 节模板 A–F）**：用户可见内容，严格按模板编号、标题、表格行列输出；回复中只允许出现模板小节。

1. **先判定，后执行**：回复第 0 节先输出任务判定一行（类型 + 内部步骤 + 模板名），随后只输出该模板小节。
2. **结构固定，细节可调**：小节编号、标题、表格维度与模板一致；实现细节（函数拆分、命名风格）在规则范围内选择。内容可详略，结构不得增减、不得自创分点。
3. **内部步骤不展示**：未执行的 S 阶段（如 T3 的 S0/S1/S2）不得在回复中出现章节标题、表格或说明文字；执行过的内部动作只以「结果行/数据表」形式落入对应模板小节。
4. **台账先行、参数同源**：涉及硬件资源变化先产出 `hardware.dts` 台账片段/全文，再写代码；参数单点定义，代码不双写魔法数。
5. **表格必须成形**：表头、分隔行、数据行齐全；无内容单元格填 `—`；禁止只输出表头与分隔线、把内容散成无序列表。
6. **最小改动**：现有工程复用句柄与初始化；改动逐处列表；未授权不改已有逻辑、时钟、引脚配置。
7. 回复中禁止出现「必做动作 / 固定产出 / Gate / 阶段规程」等内部措辞；禁止输出与模板小节无关的背景科普。

## 1. 任务类型判定（第一步强制完成）

| 类型 | 判定特征 | 内部执行步骤（自检用，不展示） | 对外模板 |
|---|---|---|---|
| **T1 整机/新功能开发** | 新板级设计、≥2 类外设、从需求到完整程序 | S0→S1→S2→S3→S4→S5 | 模板 A（3.1） |
| **T2 单外设增补** | 现有工程加一类外设/一路功能（串口回显、一路 ADC、一个 PWM、一个传感器驱动） | S0简→S2片段→S3→S4→S5简 | 模板 B（3.2） |
| **T3 现有逻辑修改** | 硬件资源不变，只改参数、状态机、协议解析、已定位 bug | S3局部→S4简→S5简；**不进入 S0/S1/S2** | 模板 C（3.3） |
| **T4 故障排查** | 用户给出编译报错/HardFault/运行现象，要求定位修复 | P4 排查流程（debug-playbook 编号步骤） | 模板 D（3.4） |
| **T5 台账维护** | 只要求增删改 `hardware.dts` 节点，不出代码 | S1简→S2→S4台账侧 | 模板 E（3.5） |
| **T6 其他操作** | 删除/重命名/移动文件、工程配置、文档/报告维护、清理旧文件、诊断分析等不属于 T1–T5 的受控操作 | S6（操作清单→影响分析→确认→执行→验证/回退） | 模板 F（3.6） |

判定规则：

- 同时命中多类时以「用户最终目标」归类（例：「加一路 ADC 并修好读数跳变」= T2，排查步骤并入模板 B 第 6 节）。
- 置信度低时先输出一行判定理由（≤2 句）并按最接近类型执行；用户纠正后切换模板，已有内容按新模板归位。
- T3 若发现硬件资源实际也要改，升级为 T2 并改用模板 B；T5 若用户要求顺带实现，升级为 T2。
- 删除、重命名、移动、工程配置、文档/报告维护等非 T1–T5 操作判定为 T6；若同时涉及代码或硬件变更，主任务仍按 T1–T5 执行，T6 操作作为附带项在对应模板中列出，删除用 `se-delete` 承载。
- T6 不得成为绕过确认的通道：任何删除、覆盖、移动或配置修改都必须先给操作清单和影响分析，等用户确认后才执行；不得擅自清理“看起来没用”的文件。

## 2. 内部执行步骤 S0–S5（自检用，禁止复述到回复中）

> 以下各表仅用于 AI 自检；「对外落点」说明该步骤结果压缩进哪个模板小节，回复中不得保留本页表格原文。

### S0 上下文收集

| 项 | 内容 |
|---|---|
| 必做动作 | ①已知项（型号、库类型、系统形式、现有工程、现有台账）②缺失项 ③默认假设（未指定：HAL 库、裸机主循环，假设显式标注）④可复用资源（句柄、初始化函数、引脚、公共工具函数，标注文件:对象名） |
| Gate | 关键缺失（型号、库类型）≤2 个可带假设进入；超过先提问（≤2 问）；复用资源指明文件位置 |
| 对外落点 | T1→模板 1.1/1.2；T2→模板 1；T3/T4/T5 不执行 |

### S1 需求拆解

| 项 | 内容 |
|---|---|
| 必做动作 | 硬件资源表 + 软件需求表；识别隐含需求（不定长串口→DMA+空闲中断；多通道采集→扫描 DMA；电机→PWM+刹车+电流采样）；冲突预判（引脚/中断/DMA/缓冲预算） |
| Gate | 每个功能点落到资源表一行；隐含需求标注；无未解释资源空缺 |
| 对外落点 | T1→模板 2；T2 隐含需求并入模板 1；T5→模板 1；T3/T4 不执行 |

### S2 台账产出（hardware.dts）

| 项 | 内容 |
|---|---|
| 必做动作 | 按 `references/ledger-schema.md` 落笔：T1 完整 `.dts`；T2/T5 受影响节点片段；术语与字段语义照规范 |
| Gate | ①TODO 集中在汇总块/片段注释，不落地猜测整数；②`app-bindings` 引用闭合；③无引脚/中断重复占用；④参数有来源 |
| 对外落点 | T1→模板 3+4；T2→模板 2；T5→模板 2；T3 无变更时在模板 4 写「台账无变更：<节点> 保持原值」；T4 不执行 |

### S3 代码实现（五维度标准 → 分层产出 → framework 产出）

| 项 | 内容 |
|---|---|
| 必做动作 | 先按五个软件标准维度依次定结论，再落代码：①**系统架构（分层架构）确认 + 根目录骨架落地**（`architecture.md`：默认架构/用户自定义/现有工程沿用；出层级表、目录树；新建工程给分层文件夹创建清单，现有工程给「默认层→现目录」映射表；每个文件标注层内相对路径；依赖单向无环）②**模块化编程**执行（`module-convention.md` M-DEV 步骤：句柄结构体、static 私有、get/set、错误码、单向依赖）③**执行范式判定**（`software-arch.md` 第 2 节：前后台 / 事件驱动 / 抢占式多任务，出结论与理由）④**调度模式落地**（`software-arch.md` 第 3 节：与范式匹配的调度机制、时基、任务/时间变量三触发类型）⑤**设计模式选用**（`software-arch.md` 第 4 节：状态机、回调注册、句柄单例等，逐条登记落点）⑥按层产出代码（APP→MID→MODULES→PERIPHERAL，代码块前标完整相对路径；外设封装要点照 `code-rules.md`）；生成 framework.md（`framework-template.md`：T1 完整三章，T2 仅增量更新点）；最小改动登记 |
| Gate | ①架构表确认、目录骨架清单/映射表完整，依赖方向单向无环，源码全部落在层目录（根目录无散落业务源码）；②执行范式、调度模式、设计模式三结论齐全且相互匹配（范式与调度不冲突）；③参数溯源台账字段或集中宏；④现有代码非授权改动 = 0；⑤错误码/超时/中断轻量/边界检查落实；⑥framework 三章齐全（T1）或增量清单完整（T2）；运行视图耗时仅写预估值并标注；⑦安全故障动作链落地 |
| 对外落点 | T1→模板 5+6；T2→模板 1.1+3+4；T3→模板 3（diff 局部块） |

| 对外落点 | T1→模板 7；T2→模板 5+6；T3→模板 4；T5→模板 3 |

|---|---|

| 对外落点 | T1→模板 8；T2→模板 7；T3→模板 5；T4→模板 4 |

### S6 其他操作（T6：删除/重命名/移动/配置/文档/诊断）

| 项 | 内容 |
|---|---|

## 3. 固定输出模板（小节编号与标题写死；表格行列照骨架输出）

### 3.3 模板 C — T3 现有逻辑修改（含完整表格骨架）


## 5. 通用硬规则（所有模板适用，违反即返工）

1. 小节标题、编号、表格维度固定；不适用写 `N/A` 并说明，不删行删节。
2. 表格三要素齐全（表头/分隔行/数据行）；空单元格填 `—`；禁止只留表头分隔线、内容散列。
3. 未核实手册事实（AF 号、IRQn、DMA 通道/请求号、寄存器地址、电气极限）用集中宏或 TODO 注释承载并注明查阅位置，禁止猜测填值。
4. 现有 CubeMX/工程生成代码（`MX_xxx_Init`、时钟配置、MspInit）默认不改；必须改时进最小改动表并给理由。
5. 等待类代码带超时返回错误码；ISR/回调内只做搬运/置标志/提交任务，禁止阻塞发送、打印、长循环。
6. 共享缓冲 `volatile`；数组访问有边界判断；指针解引用前判空；常量入 `const`。
7. 电机/逆变/功率场景：首节判定后即给安全警示；台账与代码覆盖刹车、使能（含安全态电平）、故障动作链（故障→停 PWM→断使能）。
8. 接口返回错误码枚举或 `HAL_StatusTypeDef`；模块命名沿用台账 label 前缀（`uart1_`、`adc1_`）。
9. 回复只含模板小节；内部规程措辞（必做动作/Gate/固定产出/阶段名）不出现在回复中；未执行步骤不出现标题。
10. 结束前对照模板逐节打勾：缺节补齐、空表补行、TODO 集中列出后再回复。
11. 不生成与模板无关的 README、说明文档与装饰性内容；代码片段即交付主体（framework.md 为 S3 规定产物，不属于多余文档）。
12. 连续追问沿用首次判定类型与模板，仅补对应章节，不切换叙事结构。
13. 分层依赖单向（`architecture.md` D1–D6）：代码块标注所属层与目录；禁止反向包含与循环依赖；新文件落点先过归属决策表。
14. framework.md：T1 必须完整产出三章；T2 必须给增量更新点清单；软件架构章五维度齐全（执行范式、调度模式、设计模式、模块化要点、共享数据），范式与调度结论相互匹配；运行视图中的耗时只允许写预估值并标注 `[预估]`，实测列留空待回填，禁止编造微秒级实测数据、抢占延迟与 CPU 占用率。
15. 新模块按 `module-convention.md` M-DEV 步骤开发：句柄结构体、static 私有、get/set 接口、统一错误码；模块间数据走接口参数，不直接访问他模块私有变量。
16. 目录落点红线：业务源码必须落在 `APP/`、`MID/`、`BSP/MODULES/`、`BSP/PERIPHERAL/` 层目录内并标注完整相对路径；工程根目录只允许 `hardware.dts`、`framework.md` 与构建工程；禁止业务 `.c/.h` 散落根目录或混入只读库目录；新建工程先输出分层文件夹骨架清单，再逐文件给代码块；现有工程沿用既有目录并给映射表，不迁移旧文件。
17. T6 其他操作必须走模板 F：先操作清单、影响分析、执行预览和确认项，再执行；禁止跳过预览直接删除、移动或改工程配置。
18. 删除文件必须用 `se-delete`，并满足：用户明确要求、目标是工程内普通文件、非目录/生成目录/`.simple-embedded`/`.se-workspace`、一次 ≤10 个、删除前备份、删除后验证并给回退方式。禁止用空文件、“请手动删除”注释或 `se-file` 覆盖假装删除。
19. 当前只自动执行 `se-delete`；重命名、移动、目录创建、批量清理、运行构建/烧录等未落地协议只能给命令预览和影响分析，不得声称“已完成”。

## 6. 异常处理（内部决策规则，决策结果按模板小节呈现）

| 情形 | 内部处理规则 | 对外呈现位置 |
|---|---|---|
| 关键信息缺失且无法合理假设 | S0 Gate 拦截，一次性提 ≤2 个补全问题（含候选默认值） | 模板 0 节判定后提问；不输出 S0 表 |
| 资源冲突（引脚复用/DMA/中断不足/缓冲超 RAM） | 列冲突双方 + 原因 + ≥2 替代方案，不静默选定 | T1→2.3；T2→1.2 表；其余类型并入对应改动表 |
| 编译报错 | 升级按 T4 模板 D，先按 debug-playbook 分类定位再最小修改 | 模板 D |
| 中途改需求 | 先更新台账（S2）再改代码（S3）；差异记入最小改动表 | 对应模板改动表行 |
| 硬件事实与口头描述冲突 | 以 RM/DS/原理图为准列冲突，标注需人工确认 | 待核对事实表（T1/T2）或改动表备注（T3） |
| 越界（PCB 布线、模拟电路、选型替代评估） | 标注超出规程范围，只给软件侧配合建议 | 相关小节末一行说明 |
| T6 未支持的协议（重命名/移动/目录创建等） | 不假装执行；给命令预览、影响分析和手工步骤 | 模板 F 3.2 / 4.2 |
| T6 目标危险（目录、生成目录、`.simple-embedded`、`.se-workspace`、工程根） | 拒绝自动删除，说明原因并给替代方案 | 模板 F 1.2 / 4.2 |
| T6 操作影响构建（`C_SOURCES`、包含目录、链接脚本、Makefile） | 在影响分析中列出，先确认再执行；删除后验证构建或给构建命令 | 模板 F 2.1 / 5.1 |
