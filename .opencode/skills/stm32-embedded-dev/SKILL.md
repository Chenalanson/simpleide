# STM32 嵌入式程序开发工作流（台账先行 + 代码落地）

## Overview

本 Skill 帮助 AI 完成从功能需求到可嵌入工程的 STM32 C 程序，采用两段闭环：

1. **台账段（硬件依据）**：借鉴 DTS 结构化思路生成 `hardware.dts`，集中记录时钟、外设实例、引脚复用、中断、DMA、通道参数、外部器件连接与业务绑定视图。
2. **代码段（程序实现）**：以台账为单一事实来源，分层生成板级初始化、驱动接口、业务逻辑代码；现有工程只做最小改动续写。

闭环校验：台账记录 ↔ 代码实现双向一致；手册事实（AF 号、IRQn、DMA 映射、分频值）未核实前统一标注待核对，不编造。

## 核心原则

1. **台账先行、参数同源**：硬件资源先入 `hardware.dts`；代码中的波特率、通道号、引脚、缓冲长度等参数从台账映射而来，不在代码里另造一套魔法数。
2. **现有代码最小改动**（用户既定偏好）：先通读现有工程与台账；只追加函数、补全缺失、在指定位置插入调用；不重写已有函数、不重构已验证配置、不改已有引脚与时钟。逐处说明「文件 + 位置 + 改动原因」。
3. **事实不编造**：复用功能号、中断号、DMA 请求映射、寄存器地址、电气极限，未查手册时台账与代码同步留 `TODO` 注释，给出查阅位置（RM 章节 / DS 表号 / 原理图）。
4. **分层解耦**：板级配置层 / 驱动接口层 / 业务逻辑层；初始化与业务分离，驱动层不依赖上层状态。
5. **健壮性约束**：接口返回错误码、等待带超时、中断内轻量操作、缓冲区边界检查、共享变量 `volatile` 保护。
6. **安全前置**：电机、逆变、功率电源场景首行安全警示；刹车、使能、故障安全脚在台账与代码中同步预留，故障动作链路完整。
7. **一致性闭环**：交付前核对「台账有记录 → 代码有实现；代码使用的资源 → 台账有登记」，双向无遗漏。
8. **文件落盘规范**：台账 UTF-8 无 BOM；代码片段标注文件归属与插入位置；不生成与本任务无关的框架文件。

## 阶段 0：输入收集与补全

### 0.1 必选与可选信息

| 类别 | 必选 | 可选补充 |
|---|---|---|
| 芯片环境 | 芯片完整型号（精确到后缀，如 STM32G474RET6）；固件库类型（HAL 默认 / LL / 标准库） | 封装、主频、开发环境、现有工程文件、已有 `hardware.dts` 台账 |
| 功能需求 | 核心功能；涉及外设类别与路数 | 实例编号、速率/频率、通道用途、数据帧格式、缓冲深度、实时节拍 |
| 软件约束 | — | 是否使用 FreeRTOS、任务划分、内存预算、编码规范、现有代码风格、报错日志 |

### 0.2 缺失处理规则

1. 型号缺失先追问；暂不指定时以 STM32G474RET6 + HAL 为演示默认值，全文标注「替换后重新核对手册事实」。
2. 库类型缺失默认 HAL；用户给出 LL/标准库时切换对应函数风格，分层结构不变。
3. 外设实例缺失给建议实例并标注可调；关键参数（晶振、地址、路数）缺失给常见默认值并标注假设，无法假设时追问一次（≤2 个问题）。
4. 现有工程：先通读初始化、句柄、命名与台账（若有），列出可复用项；新代码复用句柄与风格，避免重复定义。

## 阶段 1：需求结构化解析

输出两张清单：

1. **硬件资源需求清单**：功能 → 建议外设类别/实例、路数、接口形态（方向/模拟数字/总线）、关键参数、隐含需求（不定长串口→DMA+空闲中断；多通道采集→扫描+DMA；电机→PWM+刹车+电流采样）。
2. **软件需求清单**：任务/循环节拍、状态机状态、数据处理流程、协议格式、错误处理要求、FreeRTOS 机制需求（队列/信号量/通知）。
3. 冲突预判：封装引脚数、复用冲突、DMA/中断资源余量。

## 阶段 2：台账设计与生成（hardware.dts）

1. **节点规划表**：功能用途 → 建议实例 label → 类型 → 关键参数 → 候选引脚 → 待核对项。
2. **时钟规划**：时钟来源、目标主频、总线频率估算、定时器倍频提示（只记录规划值，不写寄存器配置）。
3. **分配原则**：引脚分组、DMA 优先级建议、中断优先级分组建议、资源预算与余量。
4. **生成台账文件**：按 `references/ledger-schema.md` 规范组织——文件头、`system-clock`、`app-bindings` 绑定视图、引脚组区、外设实例节点、安全资源预留、末尾待核对汇总块。
5. 台账语法、字段语义与模板见 `references/ledger-schema.md`；需求到字段的映射见 `references/field-mapping.md`。

## 阶段 3：程序代码生成（分层）

### 3.1 技术栈与框架确认

按阶段 0 结论确定库风格与是否 RTOS；代码目录与文件命名遵循 `references/coding-guide.md` 第 3 节。

### 3.2 板级配置层

- 对照台账逐实例生成初始化（GPIO/USART/ADC/TIM-PWM/SPI/I2C/CAN/DMA/NVIC）；参数取自台账字段（同源规则见 coding-guide.md 第 2 节）。
- 已有 CubeMX/工程初始化不重写；只补充用户层回调与缺失模块，注明「保留生成代码，勿手改」。
- 待核对值集中到 `bsp_conf.h` 宏定义并带 TODO 注释，不散落在函数体。

### 3.3 驱动接口层

- 模块前缀函数（`uart2_`、`adc1_`、`bus_i2c1_`）；打开/读写/启停/错误状态；等待接口带超时返回。
- 外部器件封装寄存器读写；协议帧解析与发送接口。

### 3.4 业务逻辑层

- 主循环状态机（`switch-case`/函数指针表）或 FreeRTOS 任务模型；采样处理、滤波、控制逻辑、协议业务。
- 周期节拍、缓冲与队列设计；错误上报与降级路径。
- 安全场景：故障检测 → 停 PWM → 关使能的动作链在业务层落地，与台账安全节点对应。

### 3.5 现有工程接入

- 给出每个片段的文件路径与插入位置；新功能优先独立 `.c/.h`；`main()` 初始化序列中按依赖顺序插入调用。
- 遵守 `references/coding-guide.md` 第 14 节最小改动规则；修改现有行时输出「原值→新值→原因」说明。

外设代码要点、骨架约束与 RTOS 机制选择见 `references/coding-guide.md`。

## 阶段 4：台账-代码一致性与硬件核对清单（强制输出）

1. **一致性核对表**（台账 ↔ 代码）：实例、引脚、参数、通道顺序、中断/DMA、安全节点逐项对照，标注一致/待改/缺失。
2. **硬件事实核对**（手册级必核）：AF 号、IRQn、DMA 映射、器件地址、频率极限；按 `references/checklist.md` 一级清单裁剪。
3. **参数复算**（二级）：波特率误差、PWM 频率/占空比、ADC 转换时间、总线速率；公式见 `references/checklist.md` 第 4 节。
4. **健壮性与安全**（三级）：错误返回、超时、中断轻量、边界检查、栈/缓冲预算、故障安全态。
5. 每项标注「已核对 / 待核对 / 来源（RM 章节、DS 表号、原理图网络名）」。

## 阶段 5：调试辅助与优化建议

1. **构建验证**：给出编译命令与预期检查点；编译报错按 `references/debug-guide.md` 第 2、3 节定位并给最小修改。
2. **运行期排查**：用户反馈现象后，先按台账联动法（debug-guide.md 第 6 节）对照台账与代码差异，再按故障树（第 5 节）从易到难排除；HardFault 按第 4 节栈帧回溯。
3. **优化方向**：RAM/Flash 占用（常量入 Flash、缓冲收敛）、执行效率（DMA 替代轮询）、功耗（未用脚处理、低功耗模式预留）、代码可维护性（注释与宏收敛）。
4. **扩展提示**：新增外设时先补台账节点再补代码；RTOS 迁移/多板复用的注意点说明。

## 标准输出结构（固定章节顺序）

```
1. 需求清单（硬件资源需求 + 软件需求 + 冲突预判）
2. 台账设计（节点规划表 / 时钟规划 / 分配原则 / 资源预算）
3. hardware.dts 台账完整内容（标注保存文件名与路径）
4. 程序代码（按层输出：配置层 → 驱动层 → 业务层；标注文件归属与插入位置；最小改动说明）
5. 台账-代码一致性表 + 三级硬件核对清单
6. 构建验证命令、调试排查指引与优化建议
```

用户只要求「补一个外设驱动 / 改一段逻辑 / 修一个报错」时，可省略台账规划章节，但一致性核对与改动说明不可省略；若涉及新硬件资源，先补台账节点再给代码。

## 异常与边界处理

1. 信息严重不足：暂停生成，补问 1~2 个决定性参数（型号、库类型、关键引脚约束）。
2. **资源冲突**（引脚复用冲突、DMA/中断不足）：列出冲突双方与替代方案，不静默选定。
3. **编译报错**：先分类（语法/声明/链接/库版本），定位文件行号给最小修改，不整体重写。
4. **运行异常**：先索要素象、台账片段、相关代码与观测值；按「时钟 → 引脚/映射 → 使能与初始化 → 参数值 → 业务逻辑」排除，不武断下结论。
5. **越界说明**：不做 PCB 布线与模拟电路设计；不替代 RM/DS 结论；安全相关代码仅为逻辑参考，须经硬件测试与保护验证。
6. **新旧内容冲突**（重复句柄、重复节点、引脚占用）：先指出冲突点与复用方案，再产出新增内容。
