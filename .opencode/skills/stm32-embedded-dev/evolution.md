# Skill 自我进化规则（evolution.md）

本文件是 `stm32-embedded-dev` 的进化层。它不替代 `SKILL.md`、`architecture.md`、`software-arch.md` 等规范；当用户明确纠正长期可复用的做法时，把新规则记录到 **用户级 evolution 文件**，后续请求在 L0 O1–O14 与硬件事实之下优先遵守；用户偏好不得覆盖 O 规则。

## 1. 什么时候记录

适合记录：

- 目录归属：例如“应用任务放 `APP/tasks/`，不要放 `Core/Src`”。
- 命名与接口：例如“串口模块统一叫 `bsp_usart`，初始化返回 `err_code_t`”。
- 分层与依赖：例如“器件驱动只能调用 PERIPHERAL，不得 include APP”。
- 调度/状态机：例如“保护任务必须放主循环，不放进 1ms 调度槽”。
- 交付流程：例如“涉及硬件资源变更时先更新 `hardware.dts`；涉及分层/调用链变更时同步 `framework.md`；纯逻辑修改不强制改台账”。
- 用户长期偏好：注释语言、错误码风格、文件拆分粒度、Mermaid 图要求等。

不要记录：

- 一次性任务需求、临时调试结论、具体工程私有业务逻辑。
- API Key、密码、客户隐私、完整源码或大段代码。
- 与芯片手册/电气事实冲突、无法验证的猜测。
- 仅对当前文件有效的局部修改。

## 2. 记录格式

每条规则保持一句话，包含“场景 + 做法 + 原因（可选）”：

```text
- 目录：应用任务放 APP/tasks/，不要在 Core/Src 新增业务文件。
- 命名：外设驱动统一 bsp_<外设>.c/.h，模块驱动统一 bsp_<器件>.c/.h。
- 流程：修改外设或引脚配置前先更新 hardware.dts，再改初始化代码；纯逻辑修改不要求改台账。
```

规则必须可执行、可复用，避免“写得好一点”这类空泛表述。

## 3. 提议方式（AI 输出协议）

当用户提出长期偏好或纠正时，在正常回答末尾附一个四反引号的进化块：

````se-evolve
- 目录：应用任务放 APP/tasks/，不要在 Core/Src 新增业务文件。
- 命名：外设驱动统一 bsp_<外设>.c/.h。
````

**契约注记（协议层限制，不是任务 accept）**：`se-evolve` 一次最多 5 条，每条不超过 200 字；IDE 显示 **AI 技能进化** 卡片，只有用户点击“保存规则”后才写入用户级 `evolution.md`。

规则：

- 只提议真正可复用的规则；不确定是否长期有效时先询问用户，不要擅自记录。
- 不要把 `se-evolve` 放进普通代码块，也不要用它记录密钥或工程私有数据。

## 4. 优先级与冲突

0. **L0 执行总则 O1–O14**（硬约束；任何用户偏好、evolution 规则、模板都不能覆盖）。
1. 用户当前指令。
2. 工程现状、`hardware.dts`、`framework.md` 和已验证代码。
3. 用户级 evolution 规则。
4. `SKILL.md` 与 references 默认规范。

用户级规则与默认规范冲突时，采用用户级规则并说明冲突点；但 O1–O14、硬件/电气事实与安全边界优先，用户偏好不得覆盖。

## 5. 维护

- 用户级 evolution 文件由 IDE 追加，不要手工覆盖项目文件。
- 规则重复时保留一条，过时规则应在用户确认后删除。
- 用户级规则由 IDE 写入用户级 `evolution.md`（不在本 Skill 的 `references/` 下）；导出/导入 Skill 不改变该文件位置。
